# notes — 회고와 막힌 지점

## 정본은 여기가 아니다

**회고 3줄과 막힌 지점 로그의 정본은 [`docs/PROGRESS.md`](../../docs/PROGRESS.md)다.**
여기는 작업하는 동안 손이 닿는 임시 자리일 뿐이다.

자리가 셋인데 성격이 다르다.

| 어디 | 무엇을 적나 | 성격 |
|---|---|---|
| 시트의 `📝` 칸 (`workbook/phase-N/lab-N.M.md`) | 랩을 **하는 중에** 튀어나온 관찰과 의문 | 임시. 다듬지 않은 날것 |
| `workbook/notes/` (여기) | 칸에 안 들어가는 긴 메모, 딴짓 기록, 실험 로그 | 임시. 형식 자유 |
| **`docs/PROGRESS.md`** | 랩이 **끝난 뒤** 추린 회고 3줄, 막힌 지점, 체크박스 | **정본.** 커밋되고 남는다 |

**흐름은 한 방향이다.**

```
시트 📝 칸 / notes/     →   랩 끝날 때 추려서   →   docs/PROGRESS.md
  (작업 중 임시 메모)                              (정본 · 커밋 대상)
```

- **랩을 끝낼 때 옮긴다.** 하루 루프 ⑦번이 그 단계다
  ([학습계획서 3절](../../docs/03-학습계획서.md#3-하루-루프))
- 옮기고 나면 여기 메모는 지워도 되고 남겨 둬도 된다.
  단 **PROGRESS.md에 없는 회고는 없는 것으로 친다**
- **반대 방향은 없다.** PROGRESS.md에서 여기로 베껴 오지 마라.
  같은 내용이 두 군데 있으면 둘 다 안 믿게 된다

## 회고 3줄 — 형식은 고정이다

```
### YYYY-MM-DD — Lab N.M <랩 제목>
- 배운 것:
- 헛짚은 것:
- 다음에 확인할 것:
```

**"잘 됐다"는 기록이 아니다.** 틀렸던 생각을 적어야 나중에 쓸모가 있다.

`헛짚은 것`이 비어 있는 회고는 대개 회고를 안 한 것이다.
막힘 없이 끝났더라도 "어디를 의심했는데 아니었나"를 떠올려 봐라.

## 막힌 지점 로그 — 막힌 그 순간에 적는다

**해결한 뒤에 적으면 원인이 당연해 보인다.** 그러면 기록할 가치가 사라진다.
30분을 넘겼으면 해결 전에 일단 한 줄 적어라.

[PROGRESS.md의 표](../../docs/PROGRESS.md#막힌-지점-로그)에 있는 열이 그대로 작성 지침이다.

| 열 | 무엇을 적나 | 나쁜 예 | 좋은 예 |
|---|---|---|---|
| 증상 | **화면에 나온 것** 그대로 | "테스트가 안 됨" | `ModuleNotFoundError: No module named 'bbschain'` |
| 내가 의심한 원인 | 그때 실제로 의심한 것. **틀린 채로 적는다** | (비움) | "테스트 파일 경로가 틀린 줄 알았다" |
| 실제 원인 | 알고 나서 채운다 | "설정 문제" | "src 레이아웃인데 패키지가 설치 안 돼 있었다" |
| 해결 방법 | 다음에 똑같이 따라 할 수 있게 | "고침" | "`uv sync` 후 `.pth` 파일 확인" |
| 소요 | 실제로 쓴 시간 | | "40분 (L1까지 열었음)" |

**`내가 의심한 원인` 열이 이 표의 핵심이다.**
실제 원인만 적으면 그냥 FAQ가 된다.
틀린 가설이 남아 있어야 **"나는 어떤 방향으로 잘못 짚는 사람인가"** 가 보인다.

각 시트의 **"4. 막히면"** 절에 힌트를 연 시각을 적는 표가 있다.
그 시각도 여기 `소요` 열과 함께 옮겨 두면 자기 속도를 가늠할 수 있다.

에스컬레이션 규칙 자체는
[학습계획서 5절](../../docs/03-학습계획서.md#5-막혔을-때-에스컬레이션-규칙)이 정본이다.
30분 자력 → L1 → 1시간 → L2 → 2시간 → L3 → code-reviewer에 **리뷰 요청**(정답 요청 금지).

## 이 디렉터리는 마음대로 써도 된다

`notes/` 아래에는 **아무 파일이나 만들어도 된다.** 형식도 이름도 자유다. 예를 들면 이렇다.

```
notes/
├─ README.md                  ← 이 파일 (규칙)
├─ 2026-09-21-pytest-수집.md  ← 실험하다 알게 된 것
├─ 궁금한것.md                 ← 랩에서 벗어난 질문 모음
└─ scratch/                   ← 붙여넣기용 출력 쓰레기통
```

**딴짓 기록은 많을수록 좋다.**
랩에서 벗어나 파본 것은
[PROGRESS.md의 "사이드 퀘스트 / 딴짓 기록"](../../docs/PROGRESS.md)에도 한 줄 남겨 둬라.

> **글과 코드는 자리가 다르다.**
> 실행할 스크래치 코드는 여기 말고 `labs/`에 둔다 (아직 없는 폴더. 만들어 써도 된다).
> `notes/`는 글을 적는 곳이고, `labs/`는 돌리는 곳이다.
