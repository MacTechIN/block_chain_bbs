## 4. 코드를 어떤 순서로 쓰나

**1단계 — 무엇이 이걸 판정하는지 확인한다.**
이 퀘스트에는 pytest가 없다. **판정기는 Etherscan 페이지다.**
목표는 하나다. "내 블록 해시가 Input Data에 그대로 보이는 화면."

**2단계 — 만족해야 할 불변식을 확인한다.**

```
· 개인키와 RPC URL은 절대 커밋되지 않는다
· labs/sepolia_hello.py 는 src/bbschain/ 에 들어가지 않는다
```

**3단계 — 가장 단순한 것부터 채운다.** 이 순서를 권한다.
**각 단계마다 돌려 보고 다음으로 간다.**

```
1) 연결만 해 본다        → w3.is_connected(), chain_id 가 11155111 인가
2) 잔액을 찍어 본다      → 0 이면 faucet 먼저. 여기서 멈춘다
3) nonce 를 읽어 본다    → get_transaction_count
4) 트랜잭션 dict 를 만든다 → 아직 보내지 않는다. print 로 확인만
5) 서명한다             → 아직 보내지 않는다
6) 보낸다               → 여기서 처음으로 돌이킬 수 없다
7) receipt 를 기다린다   → ⏱ 이 시간을 재라. 표의 한 행이다
```

**4단계 — 값을 하나 준비해 둔다.**
`data`에 넣을 것은 **Lab 1.5에서 만든 블록 #1의 해시**다.

```
uv run bbschain dump --from 1 --to 1
```

- [ ] 블록 #1의 해시를 손에 넣었다

**5단계 — 실패 메시지를 읽고 고친다.**
랩 5절 표에 증상이 정리돼 있다. `insufficient funds`면 faucet, `nonce too low`면 이전 tx가 pending이다.
