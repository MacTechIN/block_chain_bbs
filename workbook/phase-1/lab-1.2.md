### ③ 파일을 직접 연다 ← ★ 여기가 공격이다

에디터로 `posts.json`을 연다. **3번 글의 `body`만** 완전히 다른 내용으로 바꾼다.

```

```

[3] sam: sam이 회사 돈을 횡령했다      ← 내가 방금 심은 글

## 3. 코드를 어디에 쓰나

| | |
|---|---|
| **만들 파일** | `labs/naive_board.py` |
| **시작 파일** | 없다. 30줄이니 빈 파일에서 쓴다 |
| **본선 코드인가** | 🔴 아니다. **버릴 코드다.** `src/bbschain/`에 넣지 마라 |
| **데이터 파일** | `posts.json` (현재 디렉터리에 생긴다. `.gitignore`에 있다) |

```
mkdir -p labs && touch labs/naive_board.py
```

**import는 어떻게 해석되나.** 두 가지 방법이 있다. 아무거나 골라라.

| 방법 | 필요한 것 | 돌리는 법 |
|---|---|---|
| 모듈로 import | `touch labs/__init__.py` | `uv run python -c "import labs.naive_board as b; ..."` |
| 스크립트로 실행 | 없음 | `uv run python labs/naive_board.py` |

`labs/`는 패키지로 만들어도 되고 안 만들어도 된다. **이 랩에서는 중요하지 않다.**
(`src/bbschain/` 아래는 다르다 — 거기는 항상 `__init__.py`를 만든다.

## 4. 코드를 어떤 순서로 쓰나

**1단계 — 무엇이 이걸 판정하는지 확인한다.**
이 랩에는 pytest가 없다. **판정기는 네 눈이다.**
목표는 "변조했는데 프로그램이 눈치 못 채는 화면"이다.
**그러니 목표는 잘 만드는 것이 아니라 못 막게 만드는 것이다.**

**2단계 — 만족해야 할 불변식을 확인한다.**
이 랩의 불변식은 뒤집혀 있다. **지켜지지 "않아야" 할 것들이다.**

```
· 파일을 외부에서 수정해도 프로그램이 알아채지 못한다   ← 의도된 결함
· 글을 지워도, 순서를 바꿔도 알아채지 못한다            ← 의도된 결함
```

🔴 **해시를 붙이고 싶은 충동이 들 것이다. 참아라.**
지금 방어를 붙이면 "왜 필요한지"를 영영 못 느낀다. 방어는 Lab 1.3에서 한다.

**3단계 — 가장 단순한 것부터 채운다.** 이 순서를 권한다.

```
1) 파일 경로 상수 하나
2) _load()    파일이 없으면 빈 리스트
3) _save(posts)  통째로 덮어쓰기
      → 여기서 한 번 돌려 본다. 빈 파일이 생기면 절반은 끝이다
4) add(author, body)
5) list_all()
```

**4단계 — 한 함수 쓸 때마다 돌린다.**

```
uv run python labs/naive_board.py
```

다 쓰고 한 번에 돌리면 어느 함수가 문제인지 못 찾는다.

**5단계 — 실패 메시지를 읽고 고친다.**
`ModuleNotFoundError`면 → [설정 가이드 — ModuleNotFoundError가 났을 때](../phase-0/설정-가이드.md#modulenotfounderror가-났을-때)
한글이 `\uXXXX`로 깨져 보이면 랩 5절의 표 첫 줄이다. **Lab 1.1의 인코딩 실험과 같은 이야기다.**
