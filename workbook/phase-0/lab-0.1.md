## 1. 먼저 깨져보기 ⚔

**보려는 것**: 테스트가 없으면 틀린 코드가 **아무 소리 없이** 남는다는 사실.
30초면 본다.

**먼저 아무 함수나 하나 만든다.** 무엇이든 상관없다. 두 수를 더하는 함수로 하자.

```
cat >> src/bbschain/__init__.py <<'EOF'


def add(a: int, b: int) -> int:
    return a + b
EOF
```

- [ ] 만들었다

**손으로 한 번 돌려 "잘 되네"를 확인한다.** 이게 보통 우리가 하는 확인 방식이다.

```
uv run python -c "import bbschain; print(bbschain.add(2, 3))"
```

```
5
```

- [ ] `5`를 봤다

**이제 일부러 틀리게 고친다.** `+`를 `-`로 바꾼다. 실제 프로젝트에서 오타 하나로 벌어지는 일이다.

```
sed -i 's/return a + b/return a - b/' src/bbschain/__init__.py
```

- [ ] 고쳤다

**여기가 핵심이다.** 아무것도 실행하지 말고 다음 작업으로 넘어간다고 상상해 보라.

```

- [ ] 세 명령의 결과를 눈으로 확인했다

## 3. 과제 — 무엇을, 어떤 순서로 쓰나

**만드는 파일**: `tests/test_smoke.py`
**정본은 랩 문서다** → [Lab 0.1 과제](../../docs/labs/phase-0-setup.md#lab-01--실패하는-테스트부터-보기)

> 이 시트에 과제 내용을 옮겨 적지 않는다. 정본은 한 곳이어야 한다.
> **이미 있는 `tests/test_smoke.py`를 열어 보는 것은 정답을 보는 것이다.**
> 직접 하려면 맨 위 박스대로 파일을 밖으로 옮긴 다음 시작하라.

### 코드를 쓰는 순서

막히는 대부분의 이유는 **순서가 없어서**다. 이 다섯 단계로 간다.

**1단계 — 무엇을 만드는지 먼저 읽는다.**
랩 3절에 **함수 이름 두 개**가 적혀 있다. 본문은 비어 있다.
그 두 개가 네가 채울 칸이다. 파일 위치는 `tests/test_smoke.py`다.

**2단계 — 만족해야 할 불변식을 확인한다.**
랩 3절의 "만족해야 할 불변식" 목록이 **합격 조건 전부**다.
조건을 **한 줄씩 한국어로 다시 써 본다.** 예: "import가 예외 없이 된다."
말로 못 풀면 코드로도 못 쓴다.

**3단계 — 가장 단순한 경우부터 채운다.**
두 함수를 동시에 쓰려 하지 마라. **쉬운 것 하나부터** 채우고 돌린다.
어려운 쪽은 `pass`로 비워 둬도 된다. 비어 있으면 그냥 통과로 나온다.

**4단계 — 테스트를 돌린다.**
한 줄 고칠 때마다 돌린다. **10줄 쓰고 한 번 돌리면 어디서 틀렸는지 못 찾는다.**

```
uv run pytest tests/test_smoke.py -v
```

**5단계 — 실패 메시지를 읽고 고친다.**
읽는 순서가 정해져 있다. **맨 아래 요약 → `>` 줄 → `E` 줄** 순이다.
자세한 것은 → [테스트 실행법 — 실패 메시지 읽는 순서](../테스트-실행법.md#실패-메시지-읽는-순서)

> **이 랩은 특이하다.** 만드는 것이 테스트 자신이다.
> 그래서 1단계가 "랩이 준 함수 이름을 읽는다"가 된다.
> **Phase 1부터는 1단계가 "테스트를 먼저 읽는다"로 바뀐다.** 테스트가 미리 주어지기 때문이다.

### 체크

- [ ] 시그니처와 **불변식 목록**만 보고 `tests/test_smoke.py`를 직접 썼다
- [ ] 랩이 요구한 순서를 지켰다 — **먼저 빨강을 본 다음** 통과시켰다
- [ ] 흔한 실수 표(랩 5절)는 막혔을 때만 봤다

## 6. 눈으로 확인

- [ ] 터미널 마지막 줄이 **`2 passed`** 초록이다
- [ ] 그 전에 **`1 failed, 1 passed`** 또는 `2 failed` 빨강을 봤다
- [ ] 빨강일 때의 실패 메시지를 **읽었다** — 무엇이 없어서 실패했다고 말하고 있었나?

빨강은 이렇게 생겼다. `__version__`이 없을 때 실제로 나오는 화면이다.

```
>       assert isinstance(version, str), f"__version__ 이 str 이 아니다: {version!r}"
E       AssertionError: __version__ 이 str 이 아니다: None
E       assert False
E        +  where False = isinstance(None, str)
```

**`E` 줄이 실제 값을 알려 준다.** `version`이 `None`이었다고 말하고 있다.

> 빨강은 실패 메시지를 읽는 유일한 기회다.
> 지금 이해 안 되는 메시지는 Phase 5에서 밤 11시에 테스트가 깨졌을 때도 이해 안 된다.
