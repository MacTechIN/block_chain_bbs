# Phase 0 워크북 — 판정기 만들기

**이 Phase에는 블록체인이 한 줄도 없다.** 만드는 것은 기능이 아니라 **판정기**다.

판정기가 뭔가. **"다 됐다"를 대신 말해 주는 기계**다. 여기서는 테스트다.

앞으로 모든 Phase의 완료 기준이 "테스트가 통과하는가" 하나다.
그 기계를 못 믿으면 나머지 전부를 못 믿는다. 그래서 이게 맨 앞에 온다.

랩 3개, 반나절이면 끝난다. **여기서 시간을 끌지 마라.**

> **시작 전에 이 두 문서를 훑어 둬라.** 랩이 아니라 참고 문서다.
> - [설정 가이드](설정-가이드.md) — 이 저장소가 어떻게 생겼나, 내 파일은 어디에 두나
> - [테스트 실행법](../테스트-실행법.md) — 테스트 명령과 실패 메시지 읽는 법

## Phase 0은 이미 완료돼 있다

세 랩 모두 **사용자 요청으로 에이전트가 대신 했다**
([PROGRESS.md 기록](../../docs/PROGRESS.md#phase-0--기반-세팅)).
`pyproject.toml`도 `tests/test_smoke.py`도 `ci.yml`도 이미 저장소에 있다.

**그래서 이 시트들을 어떻게 쓰나.** 세 갈래 중 하나를 고른다.

| 고르는 길 | 무엇을 하나 | 얻는 것 | 건너뛰는 것 | 걸리는 시간 |
|---|---|---|---|---|
| **A. 1절만 한다** (권장) | 각 시트의 **"1. 먼저 깨져보기"** 만 실행하고 📝 칸을 채운다 | 방어가 없으면 무슨 일이 생기는지 **화면에서** 본다 | 이론, 실험, 직접 만들기 | 30분 |
| **B. 1·2절 + 실험** | A에 더해 사전지식 질문에 답을 적고, `experiments/`를 돌린다 | 판정기가 **어떻게** 동작하는지 안다. pytest가 왜 2개만 도는지 설명할 수 있게 된다 | 직접 만들기 | 1시간 |
| **C. 전부 직접 한다** | 각 시트 맨 위 박스대로 되돌린 뒤 3절 과제부터 직접 쓴다 | 설정 파일을 빈 화면에서 써 본 경험 | 없음 | 반나절 |

**어느 것을 고를까.**

- **빨리 Phase 1로 가고 싶다** → A. 대행된 것은 설정 파일이고, **Phase 1부터는 전부 직접 만든다**
- **설정 파일이 뭘 하는지는 알고 넘어가고 싶다** → B. 가장 무난하다
- **남이 만든 설정 위에서 시작하는 게 찜찜하다** → C

**A를 골라도 손해가 크지 않다.** 다만 **1절은 어느 갈래에서도 건너뛰지 마라.**
먼저 깨뜨려 보는 것이 이 프로젝트의 학습 방식 전부다.

> C를 고르면 각 시트 맨 위의 "되돌리는 방법" 박스를 그대로 따라 하면 된다.
> **저장소를 망가뜨리지 않고** 출발 상태를 만드는 방법이 적혀 있다.

## 관찰 실험

튜토리얼의 "손으로 확인하기"를 **바로 돌아가는 파일**로 옮겨 뒀다.
읽고 고개를 끄덕이는 것과, 같은 코드가 조건에 따라 다르게 출력되는 것을 보는 것은 다른 일이다.

저장소 루트에서 돌린다.

```
uv run python workbook/phase-0/experiments/01_pytest_collection.py
uv run python workbook/phase-0/experiments/02_sys_path.py
uv run python workbook/phase-0/experiments/03_assert_rewrite.py
```

각각 무엇을 보여주는지는 [experiments/README.md](experiments/README.md)에 표로 있다.

**돌리기 전에 결과를 예상하고 나서 실행하라.** 예상과 다른 지점이 이 실험의 수확이다.
