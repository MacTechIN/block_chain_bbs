# 워크북 — 읽는 곳이 아니라 하는 곳

> ## 처음이라면 여기부터
>
> **→ [00-시작하기](../docs/tutorial/00-시작하기.md)** 를 먼저 읽어라. 10분 걸린다.
>
> 우리가 뭘 만드는 중인지, 블록체인이 뭔지, Phase 0부터 8까지 무슨 순서인지가 거기 있다.
> 그걸 모르는 채로 아래를 읽으면 "그래서 뭘 하라는 거지"가 된다.

`docs/`는 읽는 곳이고, **여기는 터미널을 열어 놓고 따라 하는 곳**이다.
체크박스를 켜고, 빈칸에 답을 적고, 실험 스크립트를 돌린다.
**이 폴더의 파일은 네가 고치라고 있는 것이다.**

---

## 먼저 읽을 문서 두 개

이 둘은 랩이 아니다. **앞으로 계속 돌아올 참고 문서**다. 지금 한 번씩 훑어 둬라.

| 문서 | 무엇이 들어 있나 | 언제 보나 |
|---|---|---|
| **[설정 가이드](phase-0/설정-가이드.md)** | 저장소가 어떻게 생겼나. 내 파일을 어디에 두나. `pyproject.toml`은 무슨 말인가. `uv`가 왜 필요한가 | 파일을 만들기 전에. `ModuleNotFoundError`가 났을 때 |
| **[테스트 실행법](테스트-실행법.md)** | 테스트 돌리는 명령 전부. 실패 메시지 읽는 순서. 반례 읽는 법 | 테스트를 돌릴 때마다. 빨간 화면이 안 읽힐 때 |

## 어디서 시작하나

```
cd <저장소 루트>
uv run pytest
```

`2 passed`가 보이면 출발점이 정상이다. **출발점을 모르면 뭘 깨뜨렸는지도 모른다.**

그다음 [`phase-0/README.md`](phase-0/README.md)를 연다. 이 Phase에서 할 일의 순서가 거기 있다.

## 읽기 순서 경고 — 튜토리얼을 통독하지 마라

이 프로젝트는 **Break-First** 방식이다. 먼저 깨뜨려 보고, 그다음에 읽는다.

**답을 알고 나서 공격을 재현하면 그건 재현이 아니라 확인이다.**
놀라지 않은 것은 기억에 남지 않는다.

```
랩 ① 먼저 깨져보기  →  튜토리얼 해당 절  →  랩 ③ 과제
        ⚔                    📖                ✍
   (화면에서 본 뒤)      (그제서야 연다)     (이후엔 랩 4절 힌트로)
```

**워크북 시트가 이 순서를 강제한다.** 각 시트의 2절에는 **답을 먼저 적는 칸**이 있다.
그 칸을 채운 뒤에야 튜토리얼 링크가 나온다.
칸을 비우고 링크부터 누르면 그 절은 받아쓰기가 된다.

**모른다고 적는 것도 답이다.**

## 어느 폴더가 무슨 일을 하나

| 위치 | 역할 |
|---|---|
| [`docs/labs/`](../docs/labs/) | **실습 절차** — 과제, 조건, 힌트, 검증 명령 (읽는다) |
| [`docs/tutorial/`](../docs/tutorial/) | **이론** — 랩이 던진 질문에 답한다 (읽는다) |
| **`workbook/`** (여기) | **따라 하는 곳** — 체크리스트, 답 적는 칸, 실험 스크립트 |
| `src/bbschain/` | **본선 구현 — 네가 짠다** |
| [`tests/`](../tests/) | 판정기. 이미 주어져 있다. **고쳐서 통과시키는 것은 금지** |
| `labs/` (아직 없음) | 자유 스크래치. 만들어 써도 된다 |
| [`docs/PROGRESS.md`](../docs/PROGRESS.md) | 진행의 **정본** — 체크박스, 회고, 막힌 지점 |

**내용이 겹치면 안 된다.**
워크북은 과제를 베껴 쓰지 않고 랩으로 링크만 보낸다.
이론도 설명하지 않고 튜토리얼로 보낸다.
워크북에만 있는 것은 **순서, 빈칸, 돌아가는 실험**뿐이다.

## 하루 루프 9단계 — 시트의 절 번호와 맞춰 보기

정본은 [학습계획서 3절](../docs/03-학습계획서.md#3-하루-루프)이다.
**시트의 절 번호가 이 단계와 같은 번호다.**

```
 ① 랩 열기          workbook/phase-N/lab-N.M.md  ← 여기서 시작한다
       ▼            (시트 0절: 준비 — 출발점이 초록인지 확인)
 ② 먼저 깨져보기 ⚔   시트 1절. 복붙 가능한 명령 + 📝 "네가 본 것" 칸
       ▼
 ③ 사전지식          시트 2절. 질문 3개에 먼저 답을 적고 나서 튜토리얼을 연다
       ▼
 ④ 구현             시트 3절 → docs/labs/ 의 과제로 간다
       ▼            막히면 시트 4절: 힌트 연 시각을 기록
 ⑤ 테스트           시트 5절. 검증 명령 + 통과해야 할 테스트 이름
       ▼
 ⑥ 눈으로 확인       시트 6절. 이 단계를 건너뛰면 이 프로젝트를 하는 의미가 없다
       ▼
 ⑦ 회고 3줄         시트 7절(임시) → docs/PROGRESS.md(정본)
       ▼
 ⑧ 커밋             시트 8절에 명령 예시
       ▼
 ⑨ 체크박스         docs/PROGRESS.md
```

시간이 없으면 ⑧을 미룬다. **⑥과 ⑦은 미루지 않는다.**

## Phase별 진행 현황

| Phase | 워크북 시트 | 상태 |
|---|---|---|
| 0 — 기반 세팅 | [`phase-0/`](phase-0/) — 시트 3개 + 실험 3개 | 있음 (랩 자체는 🤖 대행 완료) |
| 1 — 단일 노드 체인 + 게시판 코어 | [`phase-1/`](phase-1/) — 시트 6개 + [시작 파일](phase-1/starter/) 7개 + 실험 3개 | 있음 |
| 2 이후 | — | 해당 Phase의 **랩이 작성될 때** 같이 만든다 |

**Phase 1부터는 직접 코드를 쓴다.** 빈 파일과 마주하지 않도록 [시작 파일](phase-1/starter/)을 준비해 뒀다.
함수 이름과 타입과 지켜야 할 조건은 적혀 있고 본문만 비어 있다. 랩이 시킬 때 하나씩 복사해 가서 채우면 된다.

Phase 2부터 미리 쓰지 않는 것은 방침이다.
**앞 Phase에서 실제로 무엇에 막혔는지를 보고 난이도를 정하기 위해서다**
([학습계획서 머리말](../docs/03-학습계획서.md)).

## 규칙

- 🔴 **`tests/`를 고쳐서 통과시키지 마라.** 테스트가 틀린 것 같으면 그것도 리뷰 요청감이다
- 🔴 **정답 코드를 요청하지 마라.** 막히면 단계를 밟는다
  ([에스컬레이션 규칙](../docs/03-학습계획서.md#5-막혔을-때-에스컬레이션-규칙)):
  30분 자력 → L1 → 1시간 → L2 → 2시간 → L3 → code-reviewer에 **리뷰** 요청
- 시트의 `📝` 칸은 **작업 중 임시 메모**다. 랩이 끝나면 `docs/PROGRESS.md`로 옮긴다
  ([그 관계는 `notes/README.md`](notes/README.md))
- 실험 스크립트에는 **랩 과제의 답이 없다.** 도구일 뿐이니 마음 놓고 돌려라
- 시트를 고쳐도 된다. **네 것이다.** 단 `docs/` 아래는 문서의 정본이니 임의로 고치지 않는다
