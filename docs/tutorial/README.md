---

**이 문서군의 역할은 이론 해설이다.**

각 랩에는 **"2. 사전지식 체크"** 라는 절이 있고, 거기 질문 3개가 들어 있다.
**그 질문들의 답이 여기 있다.**

랩은 "무엇을 만들어라"를 말한다. 튜토리얼은 "그게 왜 그렇게 동작하나"를 말한다.

---

## 읽는 규칙 — 미리 읽으면 손해다

**처음부터 끝까지 읽지 마라.** 이 튜토리얼을 통독하고 랩에 들어가면 이 프로젝트는 망가진다.

이유는 이 프로젝트가 **Break-First** 방식이기 때문이다
([학습계획서 1절](../03-학습계획서.md#1-이-학습법의-전제)).
허술한 것을 먼저 만들고, 내 손으로 깨뜨리고, 그다음에 고친다.

**답을 알고 공격을 재현하면 그건 재현이 아니라 확인이다.**
"prev_hash가 변조를 막는다"를 먼저 읽어 버리면, 게시판 파일을 고쳤는데 프로그램이 눈치도 못 채는 장면을
봐도 놀랄 수 없다. 놀라지 않은 것은 기억에 남지 않는다.

**그래서 순서가 정해져 있다.**

```
랩 "1. 먼저 깨져보기"를 실제로 해본 뒤  →  이 튜토리얼의 해당 절  →  랩 "3. 과제"
                   ⚔                              📖                        ✍
```

- 랩 ①을 **화면에서 직접 보기 전에는** 대응하는 절을 열지 않는다.
- 랩 ③(과제)을 시작한 뒤에는 이 문서로 오지 않는다. **랩 4절의 힌트 3단**으로 간다. 그게 막혔을 때의 자리다.
- 그래서 모든 절 맨 위에 **"언제 읽나" 박스**가 붙어 있다. 그 한 줄만 지키면 된다.

## 다른 문서와의 관계

| 문서 | 역할 |
|---|---|
| [시작하기](00-시작하기.md) | **전체 배경** — 뭘 만드는지, 블록체인이 뭔지, 왜 이 순서인지 |
| [개발계획서](../01-개발계획서.md) | **WHAT / WHEN** — Phase, DoD, 기술 스택, 코드 구조 |
| [기술리서치](../02-기술리서치.md) | **외부 자료** — 저장소 평가, 라이브러리 비교, 사양 원문 **링크** |
| [학습계획서](../03-학습계획서.md) | **규칙** — 랩 템플릿, 힌트 3단, 에스컬레이션 |
| [랩](../labs/) | **실습 절차** — 과제, 불변식, 힌트, 검증 |
| [워크북](../../workbook/) | **손을 움직이는 자리** — 따라 할 순서와 빈칸 |
| **튜토리얼** (여기) | **이론 해설** — 랩이 던진 질문에 답한다 |

경계는 엄격하다.

- 튜토리얼은 **외부 링크를 나열하지 않는다.** 더 볼 자료는 각 절 끝에서 `→ 기술리서치 #앵커`로 넘긴다.
- 튜토리얼은 **랩의 과제를 다시 쓰지 않는다.** "무엇을 만들어라"는 랩의 몫이다.
- 🔴 **튜토리얼에 정답 구현 코드는 없다.** 개념을 확인하는 3~10줄짜리 미니 실험만 있다.
  랩 과제 함수의 동작하는 구현이 여기서 발견된다면 그건 버그다.

## 전체 로드맵

| Phase | 이 Phase에서 다루는 이론 | 튜토리얼 |
|---|---|---|
| 0 | pytest 수집 규칙과 실패 메시지, src 레이아웃과 editable install, 락 파일과 CI 재현성 | [phase-0.md](phase-0.md) |
| 1 | 암호학적 해시의 성질, 정규 직렬화(canonical bytes), 해시 체인과 파손 전파, 머클 트리 | `phase-1.md` |
| 2 | 조회 API 설계, 저장 추상화(JSON → SQLite), 매 조회 검증의 비용 | Phase 2 진입 시 |
| 3 | 공개키 암호와 ECDSA, 주소 유도, nonce와 리플레이 방지 | Phase 3 진입 시 |
| 4 | 작업증명, compact target(nBits), 난이도 재조정, 타임스탬프 규칙 | Phase 4 진입 시 |
| 5 | gossip 전파, 초기 블록 동기화(IBD), 고아 블록, 누적 난이도 fork choice와 reorg | Phase 5 진입 시 |
| 6 | 이중지불 확률과 확률적 완결성, 이기적 채굴, 일식 공격, 자원 고갈 | Phase 6 진입 시 |
| 7 | 노드 운영, 장애 주입, 공개 테스트넷 앵커링과 온체인 대조 | Phase 7 진입 시 |
| 8+ | 확장 트랙 — 고르는 것에 따라 다름 | — |

**Phase 0·1만 지금 작성돼 있다. Phase 2부터는 해당 Phase의 랩이 작성될 때 같이 쓴다.**
이 프로젝트가 이미 그 방식이다 — 랩 본문도 "Phase에 진입할 때" 쓴다
([학습계획서 머리말](../03-학습계획서.md), [7절 랩 인덱스](../03-학습계획서.md#7-랩-인덱스)).
앞 Phase에서 실제로 무엇에 막혔는지를 보고 나서 다음 Phase의 해설 깊이를 정하기 위해서다.
